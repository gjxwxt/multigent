# 原型生命周期有界性、代码与Preview单源真理 (SSOT) 及设计门豁免判定

**Decision**

1. **原型生命周期有界性（Bounded Prototype Lifecycle）**：
   - OpenDesign（OD）原型的有效生命周期**严格截至其所支撑的任务分支合入主干（PR merge）为止**。
   - 一旦任务合入，该原型的使命即告终结并转为历史静态归档，不再作为后续任务的基线，杜绝在系统内沉淀与真实代码脱节的陈旧原型。
   - 在 1 → N 阶段若遇到页面难以用文字描述的新子模块，可局部召唤 OD 出具针对该新增子模块的增量原型，其生命周期同样只到该任务合入为止。

2. **单源真理（Single Source of Truth, SSOT）= 真实代码 + 实时 Preview**：
   - 仓库中的真实代码以及由其在沙箱容器中运行拉起的 **Preview 抽屉**，是全系统的唯一真理。
   - 彻底免除“代码修改后反向同步回 OpenDesign 原型”的流程设计；后续所有日常迭代 Agent 100% 以代码基线（`server/`, `web/`）与当前运行效果为上下文输入。
   - 存量项目接入（Brownfield）完全不碰 OpenDesign，依靠探测生成的 `.multigent/runtime.json` 直接拉起 Preview，存量代码本身就是其最高保真度的活原型。

3. **设计门豁免主动透出（Design Waiver Visibility）**：
   - 设计确认闸门（`design_review`）在 UI 交互层直接透出**「特批豁免设计（无需视觉原型）」**选项，不再局限于仅在快照抓取失败时被动弹出。
   - 适用于无 UI 界面的后端服务变更、页面逻辑已清晰无需先看原型、或 OD 离线时的受控流转；签署特批豁免理由后（必填，记入审计日志），携带 `design_waived: "true"` 直接准入后续环节。

4. **MVP 人机协同标准化 Loop**：
   - **新项目立项 (0 → 1)**：走一次 `greenfield`（带 OD），由模型生成高保真视觉稿定调，产出首版代码；
   - **存量项目接入 (Brownfield)**：走 `brownfield` 六步就绪流水线，纯代码探测直接拉起 Preview，零原型负担；
   - **日常高频迭代 (1 → N，95% 场景)**：无论新老项目，一律走 `unified` + Preview 抽屉验收。OD 仅作为低频工具在“文字难以说清视觉”时被临时召唤，且产物用完即归档。

---

**Reason**

1. **结构性理由：代码包含原型无法表达的状态与行为**：
   - 生产代码包含了复杂的应用状态管理、组件生命周期、动态路由、权限校验、响应式断点、网络抖动重试及异常降级逻辑；这些运行特征是任何静态或纯 HTML 视觉原型所不具备的。强行将原型作为持久基线必然导致两者产生结构性偏离。
2. **阻断原型技术债滑坡**：
   - 若原型生命周期长期常驻，后续多次日常修改未同步原型会导致 OD 原型严重陈旧。未来某个任务一旦误读旧原型，就极易抹除主干上的最新有效代码。将原型生命周期锚定到单个任务合并，彻底消除了此类次生灾害。
3. **最大化人机协作效能**：
   - 消除维护心智负担：开发者与用户只需对 Git 代码库负责，无需在原型工具和代码仓库之间双向维护；
   - 豁免机制保证流程不被视觉工具绑架，纯逻辑与后端改动可秒级通过。

---

**Cost to reverse**

- 本判定属于纯逻辑与流程解耦约束，完全向下兼容既有工作流定义；
- 若未来引入特定设计规范系统，可作为只读设计 Token 字典接入，但代码与 Preview 作为 SSOT 的核心架构原则不可逆转。
