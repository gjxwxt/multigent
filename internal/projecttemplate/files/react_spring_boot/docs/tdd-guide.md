# 测试驱动开发 (TDD) 实践与规范指南

为保证 AI Agent 与人类团队协同交付的高质量底线，本项目强制推行测试驱动开发（Test-Driven Development）。

---

## 1. 核心流程：Red-Green-Refactor

```text
  ┌────────────────────────────────────────────────────────┐
  │ 1. 明确需求与验收标准 (Acceptance Criteria / AC)        │
  └─────────────────────────┬──────────────────────────────┘
                            │
                            ▼
  ┌────────────────────────────────────────────────────────┐
  │ 2. RED: 编写失败的测试用例                             │
  │    - 针对未实现的边界/业务写测试                         │
  │    - 运行测试，确认因功能缺失而失败                      │
  └─────────────────────────┬──────────────────────────────┘
                            │
                            ▼
  ┌────────────────────────────────────────────────────────┐
  │ 3. GREEN: 编写刚刚足以让测试通过的最简代码              │
  │    - 不过度设计，以通过测试为首要目标                    │
  │    - 运行测试，确认全绿                                  │
  └─────────────────────────┬──────────────────────────────┘
                            │
                            ▼
  ┌────────────────────────────────────────────────────────┐
  │ 4. REFACTOR: 重构优化代码结构与性能                     │
  │    - 消除重复、优化命名、加强分层                        │
  │    - 持续保持测试全绿                                    │
  └────────────────────────────────────────────────────────┘
```

## 2. 后端测试层次与规范 (`server/`)

### 2.1 Controller 层切片测试 (`@WebMvcTest`)
- **适用场景**：验证路由匹配、HTTP 状态码、JSON 序列化/反序列化、`@Valid` 校验逻辑。
- **规范要求**：
  - 使用 MockMvc 进行无损调用。
  - Mock 掉底层 Service。
  - 必须同时验证正常流（200/201）与异常流（400 校验失败、404 未找到）。
- **参考示例**：见 `src/test/java/com/example/app/controller/ItemControllerTest.java`。

### 2.2 Service 层业务单元测试 (JUnit 5 + Mockito)
- **适用场景**：验证领域规则、条件分支、复杂计算与异常抛出。
- **规范要求**：
  - 纯 Java 运行，不启动 Spring 容器，执行毫秒级返回。
  - 使用 `@Mock` 隔离 Repository。
  - 严谨验证边界条件（如空值、非法字符、重复冲突）。
- **参考示例**：见 `src/test/java/com/example/app/service/ItemServiceTest.java`。

### 2.3 集成测试 (`@SpringBootTest`)
- **适用场景**：验证全链路 Spring Bean 装配与健康探针。
- **参考示例**：见 `src/test/java/com/example/app/ApplicationTests.java`。

---

## 3. 前端测试层次与规范 (`web/`)

- **测试框架**：Vitest + React Testing Library。
- **原则**：
  - 测试用户可见的行为（如按钮点击、表单输入、提示文本呈现），而非测试组件内部 state。
  - Mock 网络请求层（`services/api.ts`），保证测试稳定离线运行。
- **参考示例**：见 `web/src/test/App.test.tsx`。

---

## 4. 自动化审查与防劣化红线

1. **测试不可删**：严禁为了让 CI 通过而删除已有断言或测试用例。
2. **拒绝盲目全 Mock**：不能只写空方法断言 `assertNotNull(service)`；必须真实检验方法调用参数与返回结果。
3. **断言清晰**：测试失败时错误信息必须具有可读性，便于定位缺陷。
